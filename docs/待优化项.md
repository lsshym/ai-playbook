# 待优化项

本文记录 Wingman 当前值得后续处理的工程优化项。已知的 `plugins/wingman` payload 迁移/同步事项暂不纳入本文。

## 1. 补充 CI 发布前检查

当前仓库没有看到 `.github/workflows/` 下的自动化检查配置。建议新增 GitHub Actions，在 pull request 和 main 分支推送时运行：

- `npm test`
- `npm pack --dry-run`

目标是让插件 manifest、skills、hooks、行为评估资产和 npm 打包内容在合并前自动校验，避免只依赖本地手动执行。

相关位置：

- `package.json`
- `tests/`
- `scripts/check-plugin.mjs`

## 2. 避免安装脚本硬编码版本号

`scripts/install-codex-wingman.sh` 中的 `VERSION="1.0.0"` 与 `package.json`、`.codex-plugin/plugin.json` 重复。发布升级时如果只改 manifest 版本，安装脚本的 cache 路径可能落到旧版本目录。

建议从 marketplace payload 的 `.codex-plugin/plugin.json` 读取版本，再构造 `CACHE_DIR`。这样安装逻辑跟插件 manifest 保持一致。

相关位置：

- `scripts/install-codex-wingman.sh`
- `.codex-plugin/plugin.json`
- `package.json`
- `tests/plugin/plugin-check.test.mjs`

## 3. 参数化 eval runner 的 Codex 配置

`skill-evals/_shared/skill-eval-runner.mjs` 当前在 `renderCodexConfig` 中硬编码了 `openai_base_url` 和模型名。真实运行 eval 时，这会把环境假设写死，不利于其他开发者复现。

建议改为从环境变量或外部配置读取，例如：

- `WINGMAN_EVAL_OPENAI_BASE_URL`
- `WINGMAN_EVAL_MODEL`
- `WINGMAN_EVAL_REASONING_EFFORT`

同时保留合理默认值，确保 dry-run 和测试不依赖私有环境。

相关位置：

- `skill-evals/_shared/skill-eval-runner.mjs`
- `skill-evals/_shared/code-snapshot-eval.mjs`
- `skill-evals/README.zh-CN.md`

## 已完成

### 拆分运行时包与评估资产

Wingman 是 AI 插件仓库，不按 npm 包发布给最终用户。这里的“运行时包”指插件平台会读取的 manifest、hooks、skills、marketplace payload 等运行入口，而不是 `npm publish` 产物。

已完成第一阶段边界检查：

- `package.json.files` 保持不变，继续包含 `skill-evals/`，因为这里不作为 npm 发布面处理。
- `scripts/check-plugin.mjs` 增加插件运行入口边界检查，禁止 runtime manifest 或 marketplace 入口指向 `.eval-runs/`、`skill-evals/`、`tests/`。
- `tests/package/package-fixtures.test.mjs` 增加负向 fixture，确保 `.codex-plugin/plugin.json`、`.cursor-plugin/plugin.json`、`hooks/hooks-cursor.json`、`.agents/plugins/marketplace.json` 等运行入口误指向评估或测试资产时会报错。
- `plugins/` 暂时保留，因为 Codex marketplace payload 迁移暂不处理。

当前分层原则如下。

### 插件运行内容

这些内容是插件平台安装或启动时会直接读取的内容：

- plugin manifest
- `.agents/`
- `.claude-plugin/`
- `.codex-plugin/`
- `.cursor-plugin/`
- `skills/`
- `hooks/`
- `assets/`
- README、LICENSE、PRIVACY、TERMS

如果 Codex marketplace 仍依赖内嵌 payload，则 `plugins/` 也属于运行面。等 payload 迁移完成后，再评估是否调整。

### 开发与评估内容

这些内容保留在 Git 仓库里，用于开发、测试、评估，但不应被插件 runtime manifest 直接引用：

- `skill-evals/`
- `.eval-runs/`
- `tests/`

### 后续可选步骤

1. 在 README 的 Packaging Model 段落补一句：`skill-evals/` 是开发评估资产，不是插件运行入口。
2. payload 迁移完成后，重新评估 `plugins/` 的角色。
3. 如需继续收紧边界，可检查 README 安装说明、plugin manifest 和 hook 配置中是否出现开发资产路径。

### 已新增校验

插件运行入口现在有这些约束：

- `.codex-plugin/plugin.json` 的 `skills`、`interface.composerIcon`、`interface.logo` 不应指向 `.eval-runs/`、`skill-evals/`、`tests/`。
- `.cursor-plugin/plugin.json` 的 `skills`、`hooks` 不应指向这些开发资产。
- `hooks/hooks-cursor.json` 的 `sessionStart.command` 不应指向这些开发资产。
- `.agents/plugins/marketplace.json` 的 plugin source path 不应指向这些开发资产。

这样能避免插件平台启动时误读取评估输出或内部测试资产。

相关位置：

- `.codex-plugin/plugin.json`
- `.cursor-plugin/plugin.json`
- `.agents/plugins/marketplace.json`
- `hooks/hooks-cursor.json`
- `skill-evals/`
- `scripts/check-plugin.mjs`
- `tests/package/package-fixtures.test.mjs`
- `README.md`
