AC-01 · Run 1

后端原来返回 totalCents，现在改成 amount.total_minor_units，前端金额组件还在用旧字段。
环境标签
react-typescript
测试目的
测回答能不能看出这是 API 返回结构和 React 组件 props 的契约错位，而不是普通 undefined 小 bug。
常见错误
在父组件临时构造 { totalCents: amount.total_minor_units }，让旧组件继续假装 API 没变。
期待好改法
说明 API contract 已变；更新组件 props，或只在 API adapter/mapper 边界统一转成内部字段如 totalMinorUnits。

AC-04 · Run 1

API 的 status 被拿来填 UI 的 checkoutType，但这两个词可能不是同一个业务概念。
环境标签
react-typescript
测试目的
测回答会不会警惕“两个字段都像状态”不代表语义相同。
常见错误
直接写 checkoutType = status，把订单状态、支付状态或结账类型混在一起。
期待好改法
标记这是语义不确定的契约错位；先查 schema/docs 或问清楚含义，再决定映射关系。

AC-05 · Run 1

API 没有头像字段，但组件类型要求必须传 avatarUrl。
环境标签
react-typescript
测试目的
测回答遇到缺字段时，会不会为了过类型检查造假数据。
常见错误
塞 avatarUrl: ""，让 TypeScript 通过，但掩盖后端其实没给头像。
期待好改法
把组件契约改成 optional/nullable 并显示空状态，或明确要求 API 补头像字段。

AC-07 · Run 1

API 返回 priceInCents，但组件以为拿到的是“元/美元”主单位。
环境标签
react-typescript
测试目的
测回答能不能发现单位契约错了，不只是字段名不同。
常见错误
直接显示 API 数字，导致金额放大或缩小 100 倍。
期待好改法
明确 cents 是小单位；在固定边界转换或用清晰字段名保持单位，并补金额显示测试。
